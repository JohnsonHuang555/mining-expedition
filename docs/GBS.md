## 1. 名詞與單位

| 名詞 | 定義 |
|---|---|
| 方塊（Block） | 最小挖掘單位。每個方塊有固定的 Hardness、RequiredPower、OreType |
| 方塊索引（blockIndex） | 主線方塊編號 0–2999。深度（m）= `blockIndex / 10` 【決策 D1】 |
| 深度帶（Band） | 每 10m（100 方塊）為一帶，共 30 帶。同一帶的 Hardness 相同 |
| 門檻段（Segment） | 每 50m（500 方塊）為一段，共 6 段。同一段的 RequiredPower 相同 |
| 前線（Frontier） | 玩家已達成的最大深度的下一個方塊 |
| 回訪（Revisit） | 在已解鎖、非前線礦區的挖掘 【決策 D1】 |
| 工作量（Work） | 挖掘進度單位。挖開一個方塊需要累積 `Hardness` 點工作量 |
| 時間 | 秒（s）。伺服器內部以毫秒整數計算（見 TECHNICAL_SPEC） |
| Luck | 小數。`0.12` 代表 12%。【決策 D2】 |
| 百分比加成 | 「+3%」一律寫成乘數 `×1.03`，或小數加值 `+0.03`；兩者分別標示 |

## 2. 深度與礦區模型

### 2.1 礦區 【決策 D1】

| 礦區 ID | 名稱 | 深度 | blockIndex | 方塊數 |
|---|---|---|---|---:|
| `zone1` | 新手礦坑 | 0–100m | 0–999 | 1,000 |
| `zone2` | 水晶洞窟 | 100–200m | 1000–1999 | 1,000 |
| `zone3` | 古代遺跡 | 200–300m | 2000–2999 | 1,000 |

### 2.2 前線挖掘

- 前線方塊依 blockIndex 順序逐一往下挖。【GDD】
- 挖完 blockIndex 2999 後，主線結束，前線不再前進。結束後玩家可以繼續回訪任一礦區。【提案 P1】

### 2.3 回訪 【決策 D1】＋【提案 P2】

- 玩家可以選擇在任一已解鎖礦區挖掘。【決策 D1】
- 回訪不會改變最大深度。【決策 D1】
- 【提案 P2】回訪方塊的生成規則：
  - 回訪方塊不消耗主線 blockIndex，是無限循環的方塊。
  - 回訪方塊的 **Hardness 固定為該礦區最後一個深度帶的值**（zone1 = 1,500、zone2 = 11,500、zone3 = 32,500）。
  - 回訪方塊的 **RequiredPower 固定為該礦區最後一個門檻段的值**（zone1 = 4、zone2 = 16、zone3 = 36）。玩家可以切換回舊十字鎬，所以回訪也需要門檻檢查。
  - OreType 依該礦區的方塊組成（§6）隨機決定。
  - 掉落表使用該礦區的表（§7）。
- 選擇這個規則的原因：如果回訪從礦區頂部開始（Hardness 15），鑽石 Lv5 在 zone1 每小時可得約 **74,000** 金幣，是前線收益的 34 倍，經濟會崩潰。使用礦區底部硬度時，回訪收益穩定低於前線（見 §14.4）。

### 2.4 切換礦區

- 切換礦區時，**目前方塊的進度歸零**。【提案 P3】
- 切回前線時，從前線方塊重新開始。

## 3. 數值聚合

### 3.1 公式 【提案 P4】

玩家最終數值 = 裝備中十字鎬的基礎值 × 強化倍率，再加上收藏套組與其他加成：

```
levelStep        = Lv − 1                      （Lv.1 → 0，Lv.5 → 4）
FinalPower       = BasePower × (1 + 0.10 × levelStep)
FinalSpeed       = BaseSpeed × (1 + 0.05 × levelStep) × (1 + Σ SpeedBonus)
FinalLuck        = BaseLuck  × (1 + 0.10 × levelStep) + Σ LuckBonus
```

- `SpeedBonus`：套組提供的速度加成，彼此**相加**後再乘（兩個 +3% = ×1.06）。
- `LuckBonus`：套組提供的 Luck 加值，直接**加在 Luck 小數上**（+2% = +0.02）。
- 套組不影響 Power。
- 數值在**每個方塊完成時**取當下狀態計算（見 §4.3）。

### 3.2 數值範圍（MVP）

| 項目 | 最小 | 最大 |
|---|---:|---:|
| FinalPower | 2.0（木 Lv1） | 42.0（鑽石 Lv5） |
| FinalSpeed | 1.0 | 2.64 × 1.06 = 2.80（鑽石 Lv5 + 兩套速度套組） |
| FinalLuck | 0 | 0.168 + 0.04 = 0.208（鑽石 Lv5 + 兩套 Luck 套組） |

## 4. 挖掘規則

### 4.1 挖掘時間 【GDD】

```
Mining Time (s) = Hardness / (FinalPower × FinalSpeed)
```

實作上以「工作量」表示：每秒累積 `FinalPower × FinalSpeed` 點工作量，累積到 `Hardness` 時方塊完成。【提案 P5】
這和 GDD 的公式等價，好處是挖到一半換裝備時，已完成的進度可以正確保留。

### 4.2 最低 Power 要求 【決策 D5】

- 每個方塊有 `RequiredPower`。
- `FinalPower ≥ RequiredPower` 才能挖掘。【提案 P6：比較使用 ≥】
- Power 不足時：
  - 停止挖掘。【決策 D5】
  - 顯示裝備不足提示，引導前往 Workshop。【決策 D5】
  - 離線結算遇到時也停止，之前完成的成果保留。【決策 D5】

### 4.3 方塊完成時的結算順序 【提案 P7】

每個方塊完成時，依以下固定順序處理（亂數消耗順序與此相同，見 TECHNICAL_SPEC §6）：

1. 判定 OreType（§6）→ 獲得基礎產出。
2. 判定是否觸發額外掉落（§7.1）。
3. 若觸發：判定稀有度（§7.2）。
4. 判定物品（§7.3）與數量。
5. 寫入圖鑑紀錄（如為寶物）。
6. blockIndex + 1，進入下一個方塊；檢查 RequiredPower 與礦區邊界。

> 註：OreType 是在方塊**完成時**才決定的。玩家在挖掘過程中看不到方塊內容，可以避免客戶端預知結果。【提案 P7】

## 6. 方塊組成（基礎產出）

GDD §3.2 的方塊屬性中，`OreType` 和 `DropTable` 是兩個獨立欄位。本規格將兩者分開：【GDD】

- **基礎產出**：每個方塊完成時，必定獲得 **1 個**該方塊 OreType 的礦物。【提案 P8】
- **額外掉落**：依 DropTable 判定（§7）。

### 6.1 OreType 權重 【提案 P9】【數值】

| 礦區 | 石頭 | 煤炭 | 銅礦 | 鐵礦 | 銀礦 | 黃金 |
|---|---:|---:|---:|---:|---:|---:|
| zone1 | 60% | 15% | 13% | 12% | — | — |
| zone2 | 55% | — | — | 15% | 30% | — |
| zone3 | 50% | — | — | — | 15% | 35% |

和 GDD §3.3「主要資源」的差異：

- 所有礦區都有石頭：作為通用填充方塊，也確保後期仍能取得製作用的石頭。

## 7. 掉落系統 【決策 D2】

依決策 D2 拆成三層：觸發 → 稀有度 → 物品。

### 7.1 第一層：是否觸發額外掉落 【提案 P10】

```
TriggerProbability = min(1, LootRate[zone] × BlockMiningSeconds / 3600)
```

- `BlockMiningSeconds` 是挖開這個方塊實際花費的秒數。
- 意義：**每小時挖掘的期望觸發次數固定**，和裝備速度無關。方塊越硬，越可能觸發掉落。
- Luck 不影響觸發，只影響稀有度。【GDD：Luck 不影響挖掘速度，只影響掉落機率】

| 礦區 | LootRate（次/小時）【數值】 |
|---|---:|
| zone1 | 7.0 |
| zone2 | 5.0 |
| zone3 | 3.5 |

**為什麼不用固定的「每方塊觸發率」：**

1. 防止回訪洗寶。如果每方塊固定觸發率，用高階裝備回訪淺層，方塊秒挖，寶物產量會大增。
2. 讓掉落節奏可以直接用「每小時」設計，比較容易對應 7–14 天的目標。

**代價**：升級裝備不會提高「每小時掉落次數」，只會讓玩家挖得更深、賺更多基礎金幣。如果希望升級裝備也提高掉落數，需要改用每方塊固定觸發率，並另外設計防止回訪洗寶的機制。此點列為待審核。

### 7.2 第二層：稀有度判定 【決策 D2】

基礎機率 【GDD】：

| 稀有度 | 基礎機率 |
|---|---:|
| Common | 75% |
| Rare | 20% |
| Epic | 4.5% |
| Legendary | 0.5% |

Luck 的套用與正規化：

```
p_Rare'      = 0.200 × (1 + Luck)
p_Epic'      = 0.045 × (1 + Luck)
p_Legendary' = 0.005 × (1 + Luck)
p_Common'    = 1 − (p_Rare' + p_Epic' + p_Legendary')
```

- Luck 只放大非 Common 的稀有度，Common 吸收差額，所以總和永遠是 100%。【提案 P11】
- 這和決策 D2 的範例一致：Luck 0.12 → Legendary = 0.5% × 1.12 = 0.56%。
- 安全上限：若 `p_Common' < 0.5`，非 Common 的三項依比例縮小，使 `p_Common' = 0.5`。MVP 最大 Luck 0.208 時 `p_Common' = 0.698`，不會觸發，只是防護。【提案 P11】

| Luck | Common | Rare | Epic | Legendary |
|---:|---:|---:|---:|---:|
| 0 | 75.00% | 20.00% | 4.500% | 0.500% |
| 0.03（鐵 Lv1） | 74.25% | 20.60% | 4.635% | 0.515% |
| 0.12（鑽石 Lv1） | 72.00% | 22.40% | 5.040% | 0.560% |
| 0.208（理論最大） | 69.80% | 24.16% | 5.436% | 0.604% |

### 13.1 價格 【GDD】

```
CurrentValue = floor( BaseValue × MarketMultiplier )
```

- 只有寶物有市場價格；礦物售價固定。【提案 P14】

### 13.2 倍率生成 【提案 P24】【數值】

採用有上下限的均值回歸隨機漫步，價格會波動但會回到 1.0 附近：

```
m(today) = clamp( m(yesterday) + 0.35 × (1 − m(yesterday)) + ε, Min, Max )
ε ~ Uniform(−Step, +Step)
```

| 稀有度 | Min | Max | Step |
|---|---:|---:|---:|
| Epic | 0.80 | 1.30 | 0.12 |
| Legendary | 0.70 | 1.50 | 0.18 |

- 初始值 m = 1.0。
- 亂數由伺服器產生，客戶端無法預測（見 TECHNICAL_SPEC §9）。

### 13.3 資訊揭露 【提案 P26】

- 顯示今日價格與過去 7 天的價格走勢。
- 不顯示未來預測。

均值回歸讓「低價時留著、高價時賣」成為有效策略，配合決策 D3，形成「留著拿套組加成」和「趁高價賣掉」的取捨。

## 19. 7–14 天目標的調整建議

以下是按照目前決策**無法完全滿足**或有風險的地方。每項都只是建議，等你決定。

### A. 每天上線 1 次的玩家會超過 14 天

- **原因**：8 小時離線上限，每天上線 1 次 → 每天最多約 8.5 小時有效挖掘 → 138 小時需要約 16 天。
- **選項**：
  1. 接受：將 7–14 天的目標定義為「每天上線 2 次以上」的玩家。
  2. 離線上限改為 10 小時 → 輕度玩家約 13.2 天。
  3. 離線上限改為 12 小時 → 輕度玩家約 11.0 天，重度玩家仍約 7 天。**（建議）**
  4. 總時數降到約 115 小時 → 輕度約 13.5 天，但重度玩家會縮短到約 5.8 天，低於 7 天。
- **建議選項 3**：同時符合兩端，而且不需要改任何數值，只要修改 GDD §7.1 的上限。

### B. 在線時的節奏偏慢

- **原因**：3,000 方塊 ÷ 約 140 小時，平均每方塊約 2.8 分鐘。後期每方塊約 5 分鐘，zone3 每小時只觸發 3.5 次額外掉落；10 分鐘的在線時間大約只看到 2 個方塊、0.6 次掉落。
- 這是決策 D1（3,000 方塊）和 D6（7–14 天）共同造成的結果，不調整數值無法改變。
- **建議**（不影響經濟）：
  1. 一個方塊拆成多次揮鎬動畫，每次揮鎬顯示進度，讓畫面持續有回饋。
  2. 顯示「下一個方塊預計完成時間」與「距離下一個門檻的預估時間」。
- 如果希望在線時有更多掉落，需要改變 D1（例如更多方塊）或 §7.1 的掉落觸發規則。

### C. 離線時遇到門檻會浪費時間

- **原因**：決策 D5 規定離線遇到門檻就停止。參考玩家會在門檻前換裝，但輕度玩家可能在離線途中遇到門檻，最多浪費 8 小時。主線共 5 個 Power 門檻加 2 個解鎖點。
- **建議**：
  1. UI 顯示「預計 X 小時後遇到門檻」，提醒玩家離線前先升級。（只影響呈現）
  2. 新增規則：遇到門檻時自動切換到回訪模式繼續挖掘。（**會改變決策 D5，需要你決定**）

### D. 新手前期第一次掉落較晚

- zone1 每小時觸發 7 次，平均約 8.6 分鐘才出現第一次額外掉落、約 43 分鐘才出現第一次 Rare。
- **建議**：新手保底，例如前 20 個方塊內保證一次 Rare 掉落。（新規則，需確認）

### E. 重度玩家出售所有寶物會略低於 7 天

- 出售所有重複 Epic 和 Legendary 的重度玩家約 6.3 天完成，略低於 7 天下限。
- 影響有限，建議接受；如果要嚴格守住 7 天，可以降低寶物 Base Value 約 30%。
