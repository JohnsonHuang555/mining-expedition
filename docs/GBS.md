## 1. 名詞與單位

| 名詞 | 定義 |
|---|---|
| 方塊（Block） | 最小挖掘單位，有 Hardness、RequiredPower、OreType |
| blockIndex | 主線方塊編號 0–2999。深度（m）= `blockIndex / 10` 【決策 D1】 |
| 深度帶（Band） | 每 10m（100 方塊），共 30 帶 |
| 門檻段（Segment） | 每 50m（500 方塊），共 6 段；同段 RequiredPower 與金幣金額相同 |
| 前線（Frontier） | 最大深度的下一個方塊 |
| 回訪（Revisit） | 在比前線所在礦區淺的已解鎖礦區挖掘 【決策 D15】 |
| 重挖（Rework） | 前線卡關時，重新挖掘已探索深度的防卡死模式 【決策 D16】 |
| 有效挖掘時間 | 首次寶物保護用的計時，只累積已完成方塊的挖掘秒數 【決策 D17】（§7.7） |
| 工作量（Work） | 挖開方塊需累積 `Hardness`；每秒累積 `FinalPower × FinalSpeed` |
| Luck | 小數，`0.12` = 12% 【決策 D2】 |

#### 2.3.1 礦區邊界的回訪 【決策 D15 補充，PR #3 review 確認】

**前線所在礦區 = 下一個要挖的前線方塊（`frontierBlockIndex`）所在的礦區。** 挖完礦區最後一個方塊後，前線就屬於下一個礦區，即使下一個礦區還沒付費解鎖。這讓卡在解鎖費的玩家可以回訪剛挖完的礦區賺取資源。

| `frontierBlockIndex` | 狀態 | 前線所在礦區 | 可回訪 |
|---:|---|---|---|
| 999 | 還沒挖完 zone1 最後一個方塊 | zone1 | 無 |
| 1000 | 到達 100m，zone2 **未解鎖** | zone2 | zone1 |
| 1000 | 到達 100m，zone2 已解鎖 | zone2 | zone1 |
| 1999 | 還沒挖完 zone2 最後一個方塊 | zone2 | zone1 |
| 2000 | 到達 200m，zone3 **未解鎖** | zone3 | zone1、zone2 |
| 2000 | 到達 200m，zone3 已解鎖 | zone3 | zone1、zone2 |
| 3000 | 主線完成（P1） | — | zone1、zone2、zone3 |

- 回訪位置的 RequiredPower 仍要符合（zone1 4、zone2 16、zone3 36）。
- 前線卡在解鎖費時，重挖（§2.4）也同時可用，由玩家選擇。
- 實作：`packages/game-engine` 的 `revisitableZones(frontierBlockIndex, unlockedZone)`；Settlement / API 直接使用這個函式，不另寫判定。

### 2.4 重挖 【決策 D16】

最小可行模型：

| 規則 | 內容 |
|---|---|
| 啟用條件 | 前線卡關（RequiredPower 不足，或到達礦區底部但未付費解鎖）。還沒有可回訪礦區時也能使用 |
| 位置 | **由伺服器決定，玩家不能選擇**：從最後挖完的方塊所在深度帶往上找，第一個 `RequiredPower ≤ 目前 Power` 的深度帶 |
| 方塊 | 無限循環，使用該深度帶的 Hardness、RequiredPower 與所在礦區的掉落表 |
| 金幣 / 寶物 | 與回訪相同，各 ×0.5 【暫定】 |
| 最大深度、首次探索獎勵 | 不改變、不取得 |
| 結束 | 前線解除卡關後不能再進入重挖，回到前線 |
| 離線 | 離線前選擇重挖，離線期間繼續重挖，套用 12 小時上限（D9） |
| 隨機 | 與其他模式共用逐方塊亂數序號，切換模式無法重抽（TECHNICAL_SPEC §6） |

**為什麼位置要固定**：如果讓玩家選淺層深度帶，高階裝備重挖 0–10m（Hardness 15）每秒可挖數個方塊，賣礦物每小時可得數萬金幣。固定在「目前裝備能挖的最深已探索帶」，效率不會超過剛走過的前線（§14.3）。

**重挖與回訪的關係**：兩者都只在前線不能前進時才有意義。重挖補上兩個缺口：還沒有可回訪礦區的 0–100m，以及只有目前礦區才有的素材。

### 2.5 首次探索獎勵 【決策 D15、D16】

MVP 沒有「首次到達某深度」的獎勵。規則保留：回訪與重挖都不改變最大深度，所以未來加入的首次探索獎勵只會在前線觸發。圖鑑的 NEW DISCOVERY 是標記，不是獎勵，任何模式都會正常記錄。

### 2.6 切換模式

切換模式時，目前方塊的進度歸零。【決策 D19：P3】

## 3. 數值聚合 【提案 P4】

```
levelStep   = Lv − 1
FinalPower  = BasePower × (1 + 0.10 × levelStep)
FinalSpeed  = BaseSpeed × (1 + 0.05 × levelStep) × (1 + Σ SpeedBonus)
FinalLuck   = BaseLuck  × (1 + 0.10 × levelStep) + Σ LuckBonus
```

| 項目 | 最小 | 最大 |
|---|---:|---:|
| FinalPower | 2.0 | 42.0 |
| FinalSpeed | 1.0 | 2.80 |
| FinalLuck | 0 | 0.208 |

## 4. 挖掘規則

### 4.1 挖掘時間 【GDD】

```
Mining Time (s) = Hardness / (FinalPower × FinalSpeed)
```

以工作量實作，換裝備時進度保留。【決策 D19：P5】

### 4.2 最低 Power 【決策 D5】

- `FinalPower ≥ RequiredPower` 才能挖掘。【決策 D19：P6】
- 不足時：停止挖掘、提示、引導至 Workshop；離線也停止，保留成果。【決策 D5】
- 卡關時玩家可以選擇重挖（§2.4）或回訪（§2.3），系統不會自動切換。【決策 D5、D16】

### 4.3 方塊完成時的結算順序 【決策 D19：P7】

1. 第一層：OreType → 基礎產出
2. 第二層：礦物判定
3. 第三層：金幣判定
4. 第四層：寶物機會
5. 首次寶物保護檢查（§7.7，不消耗亂數）
6. 寫入圖鑑紀錄
7. 推進下一方塊（只有前線模式）；檢查 RequiredPower 與礦區邊界

## 7. 掉落系統 【決策 D7】

### 7.1 總覽

| 層 | 內容 | 分母 | 頻率 | Luck |
|---|---|---|---|---|
| 1 | 基礎產出 | 每方塊 | 必定 1 次 | — |
| 2 | 礦物判定（無 / 礦石包 / Rare） | 每方塊 | 1 次 | 影響 Rare |
| 3 | 金幣判定 | 每方塊 | 1 次 | — |
| 4 | 寶物機會（無 / Epic / Legendary） | 每方塊，與挖掘秒數成正比 | 期望值為每小時固定次數 | 影響 |

每層是獨立的分類分布，總和 100%；Luck 只放大稀有結果，「無」吸收差額。【決策 D2】

### 7.2 第二層：礦物判定

```
P(Rare)   = RareBase × (1 + Luck)
P(礦石包) = 15%
P(無)     = 1 − P(礦石包) − P(Rare)
```

| 礦區 | RareBase | Rare 表（權重 × 數量） |
|---|---:|---|
| zone1 | 2.5% | 銀礦 50 × 1、紫水晶 50 × 1 |
| zone2 | 3.5% | 紫水晶 65 × 2、藍寶石 35 × 1 |
| zone3 | 5.0% | 藍寶石 50 × 2、紅寶石 50 × 1 |

礦石包：依 §6 權重再抽 3 次。

### 7.3 第三層：金幣判定 【決策 D13】

```
P(金幣) = 10%
金額    = 均勻整數 [round(0.5 × Avg), round(1.5 × Avg)]
Avg     = CoinAvg[門檻段] × 模式倍率（前線 1、回訪 0.5【D12】、重挖 0.5【暫定】）
```

| 門檻段 | 0–50m | 50–100m | 100–150m | 150–200m | 200–250m | 250–300m |
|---|---:|---:|---:|---:|---:|---:|
| CoinAvg 【數值】 | 20 | 20 | 150 | 330 | 1,100 | 1,400 |

回訪使用該礦區最深門檻段的金額；重挖使用重挖深度帶所在門檻段的金額。D13 的驗證見 §14。

### 7.4 第四層：寶物機會

```
Chance       = min(0.5, TreasurePerHour[zone] × BlockMiningSeconds / 3600 × 模式倍率)
P(Legendary) = Chance × 0.10 × (1 + Luck)
P(Epic)      = Chance × 0.90 × (1 + Luck)
P(無)        = 1 − P(Legendary) − P(Epic)
```

| 礦區 | TreasurePerHour 【數值】 | 模式倍率 |
|---|---:|---|
| zone1 | 0.35 | 前線 1、回訪 0.5【D14 暫定】、重挖 0.5【暫定】 |
| zone2 | 0.25 | 同上 |
| zone3 | 0.175 | 同上 |

- Epic 從該礦區 3 件中均勻抽 1 件，不依收藏狀態調整權重。【決策 D14】
- Epic : Legendary = 9 : 1（GDD §4.1）。

### 7.7 首次寶物保護 【決策 D17】

**原則（已確認）**：只有每個帳號的第一件寶物受保護，之後完全隨機。

| 規則 | 內容 |
|---|---|
| 適用範圍 | 每個帳號的第一件寶物（Epic 或 Legendary） |
| 狀態 | 伺服器保存：`pending`（尚未取得）→ `obtained`（正常掉落取得）或 `granted`（保護發放）。轉出後永久不再觸發 |
| 有效挖掘時間 | 每完成一個方塊，加上該方塊的實際挖掘秒數（見下表） |
| 觸發 | 狀態為 `pending`、方塊完成後有效挖掘時間 ≥ 門檻，且該方塊第四層**沒有**掉落寶物時，在該方塊發放 1 件固定 Epic |
| 固定寶物 | `a_z1_lantern`（老礦工的提燈，名稱暫定）【決策 D19：P39】 |
| 稀有度 | 只會是 Epic，不會是 Legendary |
| 入帳 | 與正常掉落相同：在線直接入背包；離線放入報告並標記 NEW DISCOVERY；寫入圖鑑；計入套組 |
| 亂數 | 不消耗亂數；該方塊的四層判定照常進行，之後所有方塊的結果不受影響 |
| 出售後 | 不會再觸發（狀態已不是 `pending`） |
| 不實作 | 第二次保底、累積機率、隱藏幸運值、重複寶物保護 |
| **門檻** | **有效挖掘 4 小時**【決策 D18】（方案 C，見 §20） |

有效挖掘時間的累積方式：

### 14.4 可反覆利用的高收益策略檢查

| 策略 | 結果 |

1. **保障足夠**：最壞情況從 P99 12.6 小時降到 4 小時。四種玩家第一次回到遊戲時，有效挖掘時間都已達到約 4 小時以上（重度玩家第一次離線約 4.25 小時），所以每位玩家**最晚在第一次回到遊戲時**就會看到第一件寶物。
2. **保留驚喜**：只有約 23% 的玩家由保護取得；77% 的玩家第一件寶物仍是真正隨機掉落。B 的觸發比例將近一半，而且觸發的都是同一件固定寶物，「第一次發現」會變得千篇一律。
3. **影響極小**：平均多 0.23 件 Epic（價值約 70 金幣），主線時間差異小於 0.1 小時，zone1 套組完成率 +3 個百分點；正常掉落率不變。

如果希望玩家在**第一次在線**（通常不到 1 小時）就看到寶物，B 與 C 都做不到，需要更短的門檻，觸發比例也會更高。這屬於新的設計方向，本版不提出。

## 23. 模擬器與重現指令

模擬器預設套用 D18（`--protect 4`）。§14、§16、§17 的表格是 v1.2 在**無首次保護**下的結果，重現時加上 `--protect none`；套用保護後主線差異小於 0.2 小時（§20）。

```bash
pnpm install                                                 # 第一次：建立 workspace 連結（模擬器匯入 @mining/*）
node scripts/balance-sim.ts                                  # 全部報表（單一程序約 40 分鐘 CPU；每個方塊都走正式的請求驗證與 HMAC。可用 --only 分段平行執行）
node scripts/balance-sim.ts --only profiles --protect none   # §16
node scripts/balance-sim.ts --only revisit                   # §14.3
node scripts/balance-sim.ts --only speed                     # §7.6
node scripts/balance-sim.ts --only protection                # §20（A / B / C）
node scripts/balance-sim.ts --only stress                    # §21
node scripts/balance-sim.ts --only collection                # §22
node scripts/balance-sim.ts --only collection --revisit-treasure-mult 1   # §22 對照
node scripts/balance-sim.ts --only compare                   # §16.3（比較時固定為無保護）
node scripts/balance-sim.ts --only profiles                  # 套用 D18 的主線
```

### 23.1 統計方法

- 樣本數：玩家類型 1,000 次；首次保護 4,000 次（P99 需要較多樣本）；壓力測試 500 次。
- 種子：第 i 次模擬使用 `seed × 100003 + i`（預設 seed = 1），該次模擬的 `rngSecret = SHA-256("balance-sim:" + 種子)`，再以正式引擎的逐方塊 HMAC 亂數產生每個方塊（`digCounter` 由所有模式共用）。各方案共用同一組種子（common random numbers），差異來自規則而不是抽樣。
- 分位數：排序後線性內插（與 numpy 預設、Excel PERCENTILE.INC 相同）。時間類 P10 = 高運氣、P90 / P99 = 低運氣。
- 登入排程：每個登入時間點先領取離線報告、做決策，再在線 `sessionMin` 分鐘；離線最多推進 12 小時；超過的時間不推進、也不算閒置。
- 亂數順序：由引擎 `rollBlock` 執行，與 TECHNICAL_SPEC §6.2（RNG_VERSION 1）相同；首次保護由引擎 `firstTreasureStep` 判定，不消耗亂數。

### 23.2 模擬器與正式結算的差異

模擬器的資料、規則與**狀態轉換**都來自共用套件，與正式結算是同一份程式碼（Settlement & Actions Core 起）：

| 共用（`@mining/game-data`、`@mining/game-engine`） | 模擬器自己的部分 |
|---|---|
| 靜態資料（深度帶、門檻段、礦區、十字鎬、強化、配方、售價、寶物、套組） | 參考玩家策略：何時購買 / 強化 / 製作 / 出售 / 解鎖、卡關時選回訪或重挖、保留多少素材 |
| 玩家狀態（`PlayerGameState`） | 登入排程（在線時段、離線時段） |
| 時間推進：在線 / 離線判定（300 秒）、12 小時上限、工作量、門檻停止、首次保護（`settle`） | Monte Carlo、統計、報表 |
| 四層掉落與逐方塊 HMAC 亂數（`rollBlock`、`createBlockRng`） | 期望值試算（`expectedBlock`，供策略使用） |
| 離線報告的產生與領取、所有玩家操作與驗證（`applyAction`） | |

仍然存在的差異（玩家行為或尚未實作的伺服器功能）：

| 項目 | 模擬器 | 正式遊戲 |
|---|---|---|
| 在線結算頻率 | 每個方塊完成或每 300 秒結算一次，之後立即決策 | Client 定期呼叫（T9：5–60 秒），玩家手動操作 |
| 離線報告 | 下次登入時自動領取 | 玩家按下領取 |
| 卡關時選擇模式 | 參考玩家自動選擇 | 玩家手動選擇 |
| 製作 | 購買 / 強化前由參考玩家呼叫製作 | 玩家手動製作 |
| 市場 | 不模擬；寶物以 Base Value（倍率 1.0）出售 | 依每日倍率（Integration 階段） |

`--hardness-scale`（D11 探索用）已移除：D11 已確定不調整全域硬度，且正式結算不接受硬度參數。
